# Проект: система самообслуживания для ресторана

Полная спецификация: docs/SPEC.md. Это источник правды. Если задача или код
расходятся со спецификацией, не придумывай решение молча: назови расхождение
и предложи вариант. Если решение меняет спецификацию, обнови docs/SPEC.md.

## Архитектура в двух строках
Локальный сервер (Python, FastAPI, SQLite) в ресторане + Android-планшеты
(киоск, станция, выдача, оператор) по локальной сети. Сервер сам синхронизируется
с облачным веб-приложением, когда есть интернет. Работа без интернета обязательна.

## Инварианты (нарушать нельзя)
1. Деньги только целыми числами в минимальных единицах валюты. Никаких float.
2. Цены, скидки, суммы, статусы и время старта считает сервер. Клиенту не доверяем.
3. Все изменяющие запросы идемпотентны: UUID создаётся на клиенте, заголовок Idempotency-Key.
4. Журнальные таблицы (payment, refund, loyalty_tx, audit_log, sync_outbox) только пополняются.
   Исправление это новая запись, а не UPDATE/DELETE (кроме явно разрешённых полей статуса).
5. Бизнес-изменение и запись в sync_outbox выполняются в одной транзакции.
   Переход платежа в approved, смена статуса заказа, создание station_task, начисление баллов
   и закрытие guest_lock тоже одна транзакция.
6. Время хранится в UTC (timezone-aware). Показ в часовом поясе ресторана только на клиенте.
7. Данные карт (номер, срок, CVV) не хранить и не логировать. PIN, токены и QR-токены в логи не попадают.
8. При неизвестном результате платежа команду sale автоматически не повторять
   (сначала status по reference, затем статус unknown и ручной разбор).
9. Название, цена и prep_seconds копируются в строки заказа и задач при создании.
10. Схема БД меняется только через Alembic-миграции.

## Стек и стиль
- Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0 (типизированные модели), Alembic, pytest, ruff.
- Работа с БД синхронная (SQLite, один писатель), эндпоинты с БД объявляются как def.
  Async только для I/O с терминалом, облаком и WebSocket.
- SQLite: WAL, foreign_keys=ON, synchronous=FULL, busy_timeout. Настраивается при каждом подключении.
- UUID v7 для первичных ключей. Перечисления: text + CHECK.
- Код, комментарии, сообщения коммитов на английском. Тексты для гостей и персонала идут в ресурсы
  (i18n), а не в код.
- Тесты обязательны для всего, что касается денег, статусов, идемпотентности и платежей.
  Терминал в тестах заменяется MockTerminal.
- Новые зависимости добавлять только при необходимости, с коротким обоснованием в ответе.
- Делай только то, что входит в текущую задачу. Заготовки «на будущее» не добавлять.
